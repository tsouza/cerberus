{{- if and .Values.clickhouse.bundled.enabled .Release.IsUpgrade (eq (include "cerberus.clickhouse.mode" .) "hot-cold") }}

   WARNING — UPGRADE: the bundled ClickHouse's DEFAULT storage mode is now
   hot/cold (clickhouse.bundled.hotVolume.enabled: true + objectStorage.
   enabled: true) — a real storage-layout change from the single-volume,
   object-storage-only mode this chart used to ship as its ONLY mode. If this
   deployment predates that default (never set hotVolume.enabled itself) and
   relies on single-volume behavior, THIS UPGRADE WILL FAIL TO START
   ClickHouse: each storage mode has a distinct storage_policy name, and
   ClickHouse refuses to add a policy that does not match what is already on
   disk (an "unknown storage policy" startup error — NOT data corruption).
   Set clickhouse.bundled.hotVolume.enabled=false explicitly to keep the
   pre-existing single-volume behavior across this upgrade. Already on
   hot/cold on purpose? Ignore this. See "Upgrading into the hot/cold
   default" in docs/helm-clickhouse.md.
{{- end }}
{{- if and .Values.clickhouse.bundled.enabled .Values.clickhouse.bundled.hotVolume.enabled (not .Values.clickhouse.bundled.hotVolume.persistence.enabled) }}

   clickhouse.bundled.hotVolume.persistence — the local hot volume is a
   subpath of the `metadata` PVC (clickhouse.bundled.persistence.size:

{{- if gt (int .Values.clickhouse.bundled.replicas) 1 }}
   Because a local disk is NOT zero-copy replicated the way the object-store

   ({{ .Values.clickhouse.bundled.replicas }}) — each replica fills its own
   `metadata` PVC independently.

   enabled=true (a dedicated PVC, ideally on a faster StorageClass). See

5. Memory sizing note:
   cerberus's Go heap does not see the cgroup limit on its own, so the chart
   auto-derives GOMEMLIMIT (~80% of each container's resources.limits.memory) and
   injects it per-container — correct per-head in split mode, per-pod in monolith.
   No action needed when you set a memory limit; it is skipped when no limit is
   set. To override (or pin an exact value), set GOMEMLIMIT in extraEnv — an
   explicit entry always wins over the derived one:
     extraEnv:
       - name: GOMEMLIMIT
         value: "1228MiB"
