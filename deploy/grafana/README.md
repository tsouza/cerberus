# Grafana image

The maintained Grafana image is the Grafana the e2e lanes run. It is built on
the host that runs the lane (`just e2e-grafana-image`, tag
`cerberus-grafana:e2e`) and is never pushed to a registry. The root
`docker-compose.yml` quickstart runs the official `grafana/grafana` release
instead, under its opt-in `grafana` profile.

The image contains Grafana 12.2.9 and these fixed plugin versions:

| Plugin             | Version                                      |
| ------------------ | -------------------------------------------- |
| Metrics Drilldown  | 2.5.1 with the group-by initialization guard |
| Traces Drilldown   | 2.1.0                                        |
| Logs Drilldown     | 2.5.0                                        |
| Profiles Drilldown | 2.2.0                                        |

Metrics Drilldown is built from upstream commit
`594c2d9bca3466f7270e5c315153d9713b4b9794` with `metrics-drilldown.patch`.
It waits for a nonempty group-by selection before constructing a label-value query.
The build verifies the source archive SHA-256 and uses the upstream frozen dependency
lockfile. Build output, including browser integrity hashes, is generated by upstream's
production bundler. The unsigned-plugin exception names only
`grafana-metricsdrilldown-app`. The other plugins retain their upstream signatures.
Runtime plugin preinstallation is disabled; it must not replace the installed versions.

Build from the repository root:

```sh
just e2e-grafana-image
```

A compose stack runs it with the override that selects it:

```sh
COMPOSE_FILE=docker-compose.yml:test/e2e/grafana/compose/maintained-grafana.yml \
  docker compose --profile grafana up --wait
```

The AGPL-3.0 Metrics Drilldown source archive and patch are included in the image under
`/usr/share/grafana/plugin-source/`. Its source is also available from
<https://github.com/grafana/metrics-drilldown/tree/594c2d9bca3466f7270e5c315153d9713b4b9794>.
The plugin runs in Grafana and is not linked into the Cerberus binary.

To rebuild from the distributed source, extract the archive, apply the patch, write the
source commit into `src/version.ts`, then use the package manager pinned in `package.json`
to install with `--frozen-lockfile` and run
`pnpm exec rspack build -c ./rspack.config.ts --env production`.

Grafana's upstream image downloads its first-party plugins at startup. Those
versions can change independently of the Grafana image tag, changing routes,
tabs, and picker options covered by the browser crawl. Its preinstall list also
merges with configured entries, so pinning only some entries leaves others free
to update. Installing all four plugins in the maintained image fixes their
versions and removes the startup download race after `/api/health` becomes ready.
Plugin version changes require reviewing the browser surface inventory.
